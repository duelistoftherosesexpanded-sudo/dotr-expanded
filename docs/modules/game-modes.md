# SzGame: modes and menus

45 functions, 27,596 bytes, all byte-matching. Names are the Japanese build's symbols where it has one ([topics/jp-build-symbols.md](../topics/jp-build-symbols.md)); `func_<address>` where it has none. Descriptions are readings of the C; field and parameter meanings are interpretations unless [GAME_DATA.md](../GAME_DATA.md) records evidence. The module's place in the program: [ARCHITECTURE.md](../ARCHITECTURE.md).

- **`SzGame_Init`** `0x1a6c80`, 876 bytes: Initialises the game block gSzGame_gl: clears 560 bytes, gives 37 entries a kind, limit, start value and step, sets the remaining bytes and bit-fields and reports start values 32, 31 and 25 to SzData_SetOption(0, 0..2, v). The monster count 683 is the limit of entry 7 (kind 3): a larger monster table needs this constant raised.
- **`SzGame_DrawMenu`** `0x1a6ff0`, 904 bytes: Lays out and draws one twenty-row page of the debug menu. Takes the default message rectangle, message slots 20 and 21 and initialises the message system at the user GS address; loads the label font of each row of the current page below item 29 (page from the 3-bit field at 0x31747d, label numbers from the byte table DebugMenuOptions; columns at x 0 and 320, rows 22 apart) and two digit strips into slots 20 and 21, then flushes textures. Per row it draws a highlight (SzMsg_DrawGlass, widened to fit the digits when the item shows a value) behind the selected row, draws the label, and for items with a value draws it as count digits in the item's radix, most significant first, 22 pixels apart from x = 220 (digits below 10 from slot 20, the others from slot 21); every row's slot is freed afterwards. Field meanings assumed.
- **`SzGame_ActMenu`** `0x1a7380`, 3932 bytes: One frame of the debug start menu in the block at 0x317250. It returns while SzGame_ActMemCardProc() is not negative. The row (byte 0x317473) plus 20 x page (low three bits of 0x31747d) indexes the item table at 0x2be660; an index of 29 or more falls back to the page's first row with the row cleared. When SzFade_GetRestCount(0) is 0 it returns to the saved mode (+0x220/+0x221) with a 60-frame fade on fade 1. Pad 0 button 0x5000 moves the row (20 rows on page 0, 9 on page 1; 0x1000 up), 0xa000 toggles the page bit (0x8000 or not); both play SE 3 on a change. Otherwise an item with a non-zero limit (+0xa4) has its value (+0x138) stepped with buttons 4/8 (and 1/2 on the split items): 3 and 4 as a 0/1 thousands part and a low part modulo the limit, 17/19/22 as two 0..99 parts, 23 as 0..99 thousands and 0..999 units, 24 as two bytes, 26 skipping 0 (limit - 1 or 1), 27 skipping 0 (12 or 1); SE 3 on a change. Then the item acts: 2, 3, 4, 29, 30 nothing; 6 with 0x10 sets up constant deck 17 (item 1 value 0) or item 1 + 26 for values below 22 (else SE 6); 13 and 15 set their value to 1; 16 plays its movie; 17 loads two text files named from its two parts at 0x4000000 (the second after the first, rounded to 64 bytes), binds them and pushes the item, or plays SE 6 when none loaded; 20 and 21 copy the value's first byte to +0x22b and to the flag bit-field at +0x22e; 22 plays or (0x20) stops the BGM; 23 transfers a sound group; 24 plays or stops an SE on item 23's channel; 25 starts or stops the sound system and sets option 2; 26 sets the BGM source level; 27 sets all 854 ranks of both sides; 31 and 32 set options 1 and 0; 33 merges a text unless a file request is pending; 34 and 35 start memory-card process kinds 0 and 1; any other item is pushed (SzGame_Push(item, 0)) on 0xc0.
- **`SzGame_GetMenuNum`** `0x1a82e0`, 56 bytes: Returns the value of debug menu item index (0-36) from the menu state at 0x317250, or -1 for an index out of range.
- **`SzGame_SetMenuNum`** `0x1a8320`, 56 bytes: Stores value as debug menu item index (0-36) in the menu state at 0x317250 and returns 1; returns 0 for an index out of range.
- **`SzGame_PlayMovieNo`** `0x1a8360`, 124 bytes: Builds a movie path in a 128-byte buffer by formatting (func_0019b648, apparently sprintf) the directory from the environment variable named at data_002be80f with the file name data_0028ff10[index], then plays it with SzGame_PlayMovie(path, arg1, arg2). The index is not range-checked.
- **`SzGame_PlayMovie`** `0x1a83e0`, 312 bytes: Plays a movie file: completes all pending file requests, stops and suspends sound and terminates the sound system if it was running, re-presets models 20-29, flips the buffer and resets the GS environment for the movie player, plays it (movie_play), then calls func_001854e0(0), restores the GS environment, clears GS memory and restarts sound if it had been running. Returns the player's result.
- **`SzGame_ClearGsMem`** `0x1a8520`, 360 bytes: Clears an area of GS memory by building and sending a GS packet on DMA channel 2: a frame set-up from func_00184e10 (arguments 0, 4 and 5: apparently frame base, width and height) and a filled sprite from func_00184ff8 covering 0-0xfff with the colour from arguments 1-3, then waits (func_00185578) before and after sending. The packet helpers are unnamed SDK routines; argument meanings assumed.
- **`SzGame_InqAutoBlur`** `0x1a8690`, 12 bytes: Returns the automatic blur level (byte 0x22b of gSzGame_gl).
- **`SzGame_SetAutoBlur`** `0x1a86a0`, 40 bytes: Sets the automatic blur level (byte 0x22b of gSzGame_gl) when the value is non-negative and below the limit in word 0xf4 of the block.
- **`SzGame_InqSoftFocus`** `0x1a86d0`, 28 bytes: Returns 1 when the soft-focus flag (bit 5 of the bit-field at 0x22e of gSzGame_gl) is set, else 0.
- **`SzGame_VSync`** `0x1a86f0`, 28 bytes: Increments the vertical-sync counter (word 0 of gSzGame_gl) and returns 1.
- **`SzGame_GetHSyncCount`** `0x1a8710`, 12 bytes: Returns the count register of EE timer 1 (0x10000800), apparently used as a horizontal-sync counter.
- **`SzGame_GetFrameCount`** `0x1a8720`, 12 bytes: Returns the frame counter (word 4 of gSzGame_gl).
- **`SzGame_AddFrameCount`** `0x1a8730`, 24 bytes: Increments the frame counter (word 4 of gSzGame_gl) and returns the new value.
- **`SzGame_SetFrameSpeed`** `0x1a8750`, 12 bytes: Stores the frame speed (byte 0x22a of gSzGame_gl), the number of vertical syncs the last frame took.
- **`SzGame_GetFrameSpeed`** `0x1a8760`, 12 bytes: Returns the frame speed (byte 0x22a of gSzGame_gl).
- **`SzGame_SetStabilizer`** `0x1a8770`, 48 bytes: Stores the stabiliser flag (bit 6 of the bit-field at 0x22e of gSzGame_gl).
- **`SzGame_GetStabilizer`** `0x1a87a0`, 28 bytes: Returns 1 when the stabiliser flag (bit 6 of the bit-field at 0x22e of gSzGame_gl) is set, else 0.
- **`SzGame_Goto`** `0x1a87c0`, 164 bytes: Requests a change to mode arg0 that replaces the current one: starts a 60-frame fade on fade 0, marks a change as pending (-2 at +0x21f) with the target mode and operation 0, stores arg1 as the mode's argument in the mode stack when it is non-negative, and requests SzGame_ReqBGM(-2, 1) when arg1 is below 2. Field meanings assumed.
- **`SzGame_Push`** `0x1a8870`, 164 bytes: As SzGame_Goto but pushes mode arg0 on the mode stack (operation 1) with argument arg1, when the stack depth (+0x222) is below 7; requests SzGame_ReqBGM(-2, 1) when arg1 is below 2. Field meanings assumed.
- **`SzGame_Pop`** `0x1a8920`, 148 bytes: When the mode stack (depth at +0x222) is not empty, starts a 60-frame fade on fade 0 and requests a return (operation -1) to the mode saved on the stack; requests SzGame_ReqBGM(-2, 1) when the saved argument is below 2. Field meanings assumed.
- **`SzGame_SetMode`** `0x1a89c0`, 492 bytes: Switches to mode arg0 with stack operation arg1 (-1 pop, 0 replace, 1 push): remembers the old mode as the previous one (byte 0x21e), moves the mode stack depth by arg1 and records the new mode, terminates the old mode (SzGame_ModeTerm) unless it is pushed with a non-zero argument, resets common state (SzGame_ComInit), initialises the new mode (SzGame_ModeInit) unless it is returned to by a pop from a mode pushed with a non-zero argument, then resets the frame state and starts the mode's start-up sequence (status 3). Bit 4 of byte 0x22e is set only when both the termination and the initialisation ran and the mode is not -3 to -1, 10 or 36 (or 15 entered from mode 1). Field meanings assumed.
- **`SzGame_ComInit`** `0x1a8bb0`, 500 bytes: Resets state shared by all modes: map colours and field rates of the duel, view 0's roll, screen distance (800), camera and camera roll, the ten fog and light slots of view 0, the deformation of models 20-31, and draw flag, scale, rotation, deformation, animation direction and speed, colour, filter and intensity of all 84 models; sets the three black-out levels to 128.
- **`SzGame_ModeInit`** `0x1a8db0`, 2012 bytes: Initialises a game mode by number, using the debug menu values as parameters: loads the text and model merge files the mode needs and calls its set-up, e.g. duel (modes 0 and 1, with the rose flag, duel set-up and both players), battle (5 and 19, with both decks' leaders as units, 19 also initialising the camera), build deck (6), 3D view (7), trade (8), custom duel (9), title (10, which first plays one of two alternating movies when movie playback is enabled), campaign (11), event (12), map edit (13), face (14), slot (15) and memory-card check (36); mode -1 hides all models. Mode meanings are inferred from the callees.
- **`SzGame_ModeDraw`** `0x1a9590`, 620 bytes: Draws the current mode (SzGame_GetMode(1)) unless the 2-bit status at 0x22c is 3 or the busy byte at 0x228 is set. Mode 17 sorts a frame-buffer rectangle in the stored colour and calls lSzGame_TEXTURE_TEST for each non-zero texture word.
- **`SzGame_ModeDrawAfter`** `0x1a9800`, 176 bytes: Draws after the effects for the current mode, unless the 2-bit status at 0x22c is 3 or the busy byte at 0x228 is set: for mode 1 the duel join fade and join card, for mode 11 (with dither matrix 2) the campaign's after-draw and the faces; then the duel dialogue in either case.
- **`SzGame_ModeDrawLast`** `0x1a98b0`, 1696 bytes: Draws only when the 2-bit status at 0x22c is 3 or the busy byte at 0x228 is set, and the enable bit is set. Between SzDuel_StartWindowSessionWithPalette_Pipe and SzDuel_FinishWindowSession_Pipe it tiles window texture 6 over up to 560 cells of 18 x 24 (tile = counter / 560 % 5, cells = counter % 560, the remaining cells in the previous tile once the counter has passed 560), draws the text at 0x2be815 centred at (320, 212) with a swinging alpha, advances the counter and fade state, and hands the finished window packet through ExSortSoftFocus_Pipe to RhBase_SetVifPacketArea. The 0x317250 field meanings and the packet layout are assumed.
- **`lSzGame_TEXTURE_TEST`** `0x1a9f50`, 772 bytes: Debug view of one texture record: uploads it after the user GS area and the CLUT space (SzText_Load between texture flushes) and draws it as one sprite centred on (x + 0x800, y + 0x800), at double size when the flag is set, colour 0x80, depth 0xfffff8, texture coordinates scaled to the next power of two (at least 16) of its width (+0x54) and height (+0x56).
- **`SzGame_ModeAct`** `0x1aa260`, 2192 bytes: Runs one frame of the current mode. The two-bit status in byte 0x22c of the state at 0x317250 steps a mode start-up (3: wait for the file request, request music, arm byte 0x228; 2: wait for music loading and load the text sets of modes 1, 6 and 8; 1: wait for byte 0x228, release fade pause 1); then every frame it forwards sound requests while SzSound_IsStandby, runs SzModel_Motion for 84 models and SzEffect_TrimModule and, unless fade 1 is running, calls the Act function of the mode (20 cases; mode 17 is a pad-driven adjustment screen that ends in the inlined body of SzGame_Pop). Field meanings assumed.
- **`SzGame_ReqBGM`** `0x1aaaf0`, 596 bytes: Starts or stops the background music for request n. The kind is n % 1000 through an 18-entry jump table (-2 to 15): -2 and -1 stop the music; 0, 6, 7, 8, 9, 10 and 15 play a fixed number (7, 5, 5, 41, 3, 2, 21); 1 plays the duel music chosen by the game block word at +0x13c (five named stages, otherwise 8 or 9 by the word at +0x140 below stage 22 and 40 from 22 up) plus the thousands of n; 5 plays the campaign music chosen by the word at +0x14c through a second 10-entry table; every other kind does nothing. The second parameter is never read; it is left in its argument register at each SzSound_PlayBGM call (see that function in [engine.md](engine.md)).
- **`SzGame_ModeTerm`** `0x1aad50`, 516 bytes: Terminates a game mode by number: duel (1), battle (5), build deck (6), 3D view (7), trade (8), custom duel (9), title (10), campaign and faces (11), event (12), map edit (13), faces (14), slot (15), battle and camera (19) and memory-card check (36); after modes 1, 6 and 15 also calls SzDuel_InitCustomDuel(-1) when the next mode (byte 0x21f of the state) is 9.
- **`SzGame_GetMode`** `0x1aaf60`, 64 bytes: Returns a mode number from the mode state: for a positive argument the mode on top of the mode stack, for a negative one the previous mode (byte 0x21e), for zero byte 0x21f (the current mode, or -2 while a change is pending).
- **`SzGame_InitMemCardProc`** `0x1aafa0`, 548 bytes: Starts a memory-card procedure of kind 0-6: kind 0 TkMc_Load_Main(1) (state 2), kinds 1 and 2 request the file "%s/Merge/Icon.Mrg" under the HOME directory to be read to 0x1e301e0 (state 1), and kinds 3-6 TkMc_Custom_Main, TkMc_Trade_Load_Main, TkMc_Trade_Save_Main and TkMc_Check_Main with 1 (state 1). Then clears the last result (+0x21c), stores the kind in bits 3-5 of +0x22d and sets the second flag only for kind 2.
- **`SzGame_ActMemCardProc`** `0x1ab1d0`, 4288 bytes: Runs one frame of the memory-card dialogue over the game block at 0x317250 (text number +0x210, last result +0x21c, kind at bits 3-5 of +0x22d, step at bits 0-2 and yes/no cursor at bit 3 of +0x22e). It returns -1 when the step is 0, and 0 while SzFile_InqRequestEx reports a pending request. Otherwise a 7-entry jump table on the kind picks the card routine: 0 TkMc_Load_Main, 1 and 2 TkMc_Save_Main, 3 TkMc_Custom_Main, 4 TkMc_Trade_Load_Main, 5 TkMc_Trade_Save_Main, 6 TkMc_Check_Main. Steps 1-4 call the routine with step - 2 (step 1 counts as 2), store its result, ask lSzGame_GetMCardMsg for the text and message class, and return to step 2; then by the result high byte: 0 with a message waits for a button (mask 240; pad 1 as well for kinds 4 and 5) and ends the dialogue (step 0, text -1); 1 goes to step 5 (also 2-5 for kind 3 and 6 for kind 5; kind 6 ends at once instead); 7 clears the cursor and goes to step 3. Step 5 waits for a button, then step 0 and text -1. Kind 1 starts its save at step 1 with TkMc_Save_Main(1); kind 2 first asks with text 2505 (0xa000 moves the cursor, 0x8000 to yes, sound 3 when it changed; 192 confirms: save on yes, end on no; 32 ends). In steps 2-4 of kinds 1 and 2 a class-2 message is a yes/no question (yes: step 4; no or cancel: end for kind 1, back to step 1 with the cursor on yes for kind 2), class 3 goes to step 4 on a button and other classes end or go back. Kind 6 turns text 2482 into -1. Last, a negative text closes the popup and returns 2 when the dialogue ended through its end sequence, else 1; otherwise SzDuel_OpenMsgPopup(op, 0, 0, text) with op 6 for class 1 or 3, 7 for class 2 (bit 15 of the text set from the cursor, and the cursor cleared when the step changed this frame), else 5, and 0 is returned.
- **`lSzGame_GetMCardMsg`** `0x1ac290`, 628 bytes: Picks the memory-card message for a procedure kind and a result code: stores a text number through out and returns its message class 0-3. The default is 2482 + bit 7 of the code; the low seven bits then select a text and class through a table (0 and values of 15 or more store nothing further), and the high byte overrides it: 0x600 stores 2523 and 0x100-0x500 store 2522, 2502 or 2519 depending on the kind. Argument types assumed.
- **`lSzGame_InitMemCheck`** `0x1ac510`, 68 bytes: Initialises the memory-card check mode: clears the draw flag of all 84 models and starts memory-card procedure 6 (SzGame_InitMemCardProc(6)).
- **`lSzGame_ActMemCheck`** `0x1ac560`, 148 bytes: Runs the memory-card procedure each frame; when it ends (negative result), clears the word at +0x160 of the mode state, starts a 60-frame fade on fade 0 and requests a switch to the title mode (10) with argument 0, then SzGame_ReqBGM(-2, 1).
- **`lSzGame_TermMemCheck`** `0x1ac600`, 8 bytes: Empty: the memory-card check mode needs no termination.
- **`lSzGame_InitTitle`** `0x1ac610`, 216 bytes: Initialises the title mode: hides all 84 models and shows models 34-73; for an argument below 2 also stores 2 at data_003173b0 and resets the title state (selection and fade bytes 0x224-0x226 to 0, byte 0x227 to 0x80, the 2-bit status to 1, a hidden flag to -1 and word 8 to 0).
- **`lSzGame_TermTitle`** `0x1ac6f0`, 8 bytes: Empty: the title mode needs no termination.
- **`lSzGame_ActTitle`** `0x1ac700`, 1360 bytes: Title screen step. Runs SzGame_ActMemCardProc; result 0 or 2 ends the step; result 1 pushes mode 11, 9 or 8 for selected entry 1, 2 or 3 (the body of SzGame_Push is inlined) and sets the sound output from option 2; any other result fades two bytes in by steps of 4 up to 128, swings byte 0x227, counts to 900 before going to mode 10 while func_00197548(0x2be80f) is non-zero, moves the selection 0..3 with the pad and on confirm starts a new game (three options set to 1) or the memory card procedure with 0, 3 or 4. Field meanings assumed.
- **`lSzGame_DrawTitle`** `0x1acc50`, 44 bytes: Runs lSzGame_DrawTitle_Pipe on the current VIF packet area and stores the advanced cursor.
- **`lSzGame_DrawTitle_Pipe`** `0x1acc80`, 2544 bytes: The title screen: loads the two title images (group 9) after a CLUT area from 0x37c0, draws the logo, its fading overlay (returns early when the alpha byte is below 0x80 and the hidden flag is set), the shading rectangles, the menu rows cut by the eight bytes at 0x28ff28 with the selected row lit and the rose (lSzGame_DrawTitle_Rose_Pipe), following the title state at 0x317250; returns the cursor.
- **`lSzGame_DrawTitle_Rose_Pipe`** `0x1ad670`, 748 bytes: Builds a textured two-vertex packet (alpha 0x8000000044, colour 128 with the byte at 0x317476); when RhView_PushStack succeeds renders model index into render frame (0, 2, 50) with the view at (0, 0, -z), direction (0, 0, 1) and clip 1..512, restores the view and sorts the packet as a width x height rectangle centred on (x + 2048, y + 2048); otherwise returns the cursor unchanged.
