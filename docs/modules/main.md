# Main: start-up and main loop

9 functions, 2,172 bytes, all byte-matching. Names are the Japanese build's symbols where it has one ([topics/jp-build-symbols.md](../topics/jp-build-symbols.md)); `func_<address>` where it has none. Descriptions are readings of the C; field and parameter meanings are interpretations unless [GAME_DATA.md](../GAME_DATA.md) records evidence. The module's place in the program: [ARCHITECTURE.md](../ARCHITECTURE.md).

- **`main`** `0x1000d0`, 244 bytes: The program entry. Sets the stack pointer to 0x912000 (an inline assembly block, as C cannot express it), starts the memory manager (SzMem_Init), passes seven pairs of name strings, each with flag 1, to the SDK routine at 0x19b0f8, then returns 0 if Main_Init fails and otherwise runs Main_Loop and Main_Term and returns 0. What the seven string pairs name is not known.
- **`Main_Init`** `0x1001d0`, 380 bytes: Start-up: initialises the file system, opens the graphics base (RhBase_Init with seven constants; failure returns 0), sets the clear colour and clears GS memory, initialises text, pad, sound, model, view, fade, game, effect and debug, sets parameters for both pads, creates view 0 (failure returns 0), initialises message, data, duel and battle state and the 84 models (lMain_InitModel2; failure returns 0), then enters game mode 0x24, starts fade 1 with kill and pause flags, loads the models and returns 1. The meanings of the constants are not known.
- **`lMain_InitModel2`** `0x100350`, 364 bytes: Creates the 84 models from the 48-byte records of gMain_ModelData, returning 0 as soon as SzModel_Create fails: sets each model's position and rotation and presets its kind and value; kind 5 (indices from 30) and kind 4 (side 0 below index 25, else 1) also add a duel unit via SzDuel_AddUnit with the value converted by SzDuel_Xax2New and set its status, open rate and control rate. Returns 1. Record field meanings assumed.
- **`Main_Term`** `0x1004c0`, 84 bytes: Shut-down: destroys view 0 and all 84 models, terminates the graphics base and returns the result of SzPad_Term. The pointer return type is taken from that callee's declaration; the code only forwards it.
- **`Main_Loop`** `0x100520`, 64 bytes: Installs SzEffect_StoneProc as the vertical-sync callback (RhBase_SetVSyncCallback), then loops forever: reloads models (lMain_LoadModel) whenever SzGame_GetMode(1) is 1, then runs one frame (Main_LoopProc).
- **`Main_LoopProc`** `0x100560`, 164 bytes: One frame of the main loop: polls the pads, steps sound, services file requests, runs the current game mode, services view and duel unit requests, draws (Main_Draw), sets the frame speed from RhBase_FlipBuffer and then to 1 if the stabiliser is on (otherwise it turns the stabiliser on), then runs Main_VSync, advances the frame counter and acts on pad input.
- **`lMain_LoadModel`** `0x100780`, 148 bytes: For each of the 84 models that is ready, loads it with SzModel_Load(i, -1, -1, 1), skipping models of type 4 or 5 that have no duel unit (SzDuel_GetUnit(-1, i) is 0).
- **`Main_VSync`** `0x100820`, 48 bytes: Per-frame vertical-sync work: calls func_0019a5c8 (which other code uses as its random-number source, so apparently to advance it each frame), SzPad_VSync and SzGame_VSync, and returns 0.
- **`Main_Draw`** `0x100850`, 676 bytes: One frame of drawing. Takes the packet cursor (RhBase_GetVifPacketArea), resets the text CLUT manager and draw cache, sends RhBase_SetZBufferMode(1), ExDitherMode_Pipe(1), ExDitherMatrixEz_Pipe(1), SzView_Set_Pipe(0), the battle and duel stage and RhZSort_Finish_Pipe down the chain and stores the cursor back; mode draw; frees text request 4 when effect slots 0, 1 and 2 are idle (SzEffect_IsUse2(n, -1) == 0), 5 and 8 when 0 and 1 are idle, 6 when 1 and 2 are idle; redoes requests 4, 5, 6, 8 from offset 0x3bc0 plus the results so far; stage-after, motion blur, units; SzModel_SetMaxOT(i, 0) for i < 84; SzEffect_Draw 0..2, cards, mode draw after; when SzGame_InqAutoBlur() > 0, ExSortDispBlur(0, 0, 1, ExGetAlphaVal(0), colour) with the constant at 0x28b840 and its last byte set to level << 4; fades and SzGame_ModeDrawLast. The Japanese build's function of this name has a different body. The four-byte colour structure is assumed.
