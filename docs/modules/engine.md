# Sz: other engine modules

132 functions, 47,428 bytes, all byte-matching. Names are the Japanese build's symbols where it has one ([topics/jp-build-symbols.md](../topics/jp-build-symbols.md)); `func_<address>` where it has none. Descriptions are readings of the C; field and parameter meanings are interpretations unless [GAME_DATA.md](../GAME_DATA.md) records evidence. The module's place in the program: [ARCHITECTURE.md](../ARCHITECTURE.md). Library routines in the text (sce*, C library) carry the Japanese build's names; some of those are placed only by position and the two builds' SDK versions differ, so treat them as likely, not certain.

- **`lSzFile_SetReadRequestParam`** `0x1feda0`, 1188 bytes: Fills a file request record and returns 1, or 0 when it is rejected. Returns 0 for a null record or name. If `0x197548(0x2d0638)` (string `CDVD`) is nonzero and bit 31 of `name` is clear, it copies the name into a 128-byte stack buffer (`strcpy`, `0x19bdd8`), locates the last `/` or, failing that, the last `\` (`strrchr`, `0x19c478`), and measures the text after it (`strlen`, `0x19bef0`). It then scans the 97 records at `0x293090`: for each name containing `\` it compares the text after the separators with `strncasecmp` (`0x19c028`, given the length); on a zero result `name` becomes the 64-bit value at entry +8 OR `0x80000000`, truncated to 32 bits, and a negative `byte_size` becomes the word at entry +`0x18` shifted left 11. If bit 31 of `name` is then set: a negative `byte_size`, or a `byte_size`, `byte_offset` or positive `unknown_010` that is not a signed multiple of 2048, returns 0 (`byte_size` and `unknown_010` are only tested when positive); otherwise record +`0x20` is cleared, bit 7 of byte +`0x13` is set and record +0 receives `name & 0x7fffffff`. If bit 31 is clear: SzMem_StrDup(name) is stored at +`0x20`, zero returns 0, otherwise lSzFile_StrNormalize normalises it, the bit is cleared and +0 is zeroed. Finally it stores `fileType` as a halfword at +4, `priority` clamped to at least 0 at +6, the low 31 bits of `byte_size`, `byte_offset` and `unknown_010` at +8, +`0xc` and +`0x10` (preserving bit 31 there), clears bit 7 of bytes +`0xb` and +`0xf`, stores `unknown_014`, `callback` and `unknown_01c` at +`0x14`, +`0x18` and +`0x1c`, and returns 1.
