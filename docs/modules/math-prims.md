# Ex: 3D mathematics and primitives

50 functions, 14,300 bytes, all byte-matching. Names are the Japanese build's symbols where it has one ([topics/jp-build-symbols.md](../topics/jp-build-symbols.md)); `func_<address>` where it has none. Descriptions are readings of the C; field and parameter meanings are interpretations unless [GAME_DATA.md](../GAME_DATA.md) records evidence. The module's place in the program: [ARCHITECTURE.md](../ARCHITECTURE.md).

- **`Ex3d_RotTransPers`** `0x205440`, 496 bytes: Projects one point to the screen: copies the four floats of the input, uses the world-screen matrix (RhView_GetWorldScreenMatrix) when the matrix argument is null, sets w to 1.0 and transforms the point between RhGeom_PushMatrix and RhGeom_PopMatrix, then divides x, y and z by w. Returns 0 when z is outside 1.0-16777215.0 or x or y outside 0.0-4095.0; otherwise stores func_001a23b0 of 16x and 16y in the two 16-bit fields of the packet word and of z in its 24-bit field, writes w through the last argument when it is not null and returns 1. Argument types assumed.
- **`Ex3d_RotTransPersAuto`** `0x205630`, 672 bytes: Array form of Ex3d_RotTransPers. Sets w = 1 on the input of every type-4 packet entry, transforms them in one RhGeom_MulMatrixVectorArray call between a matrix push (the given matrix, or the world-screen matrix when it is null) and pop, divides each result by its w, returns 0 at the first result outside x,y in [0,4095] or z in [1,16777215] (earlier entries already stored), otherwise stores x and y in sixteenths and the 24-bit z in the entry and returns 1; a non-null fifth argument receives the mean w. Parameter roles and the packet and vector layouts are assumed.
- **`Ex3d_RotTransPersAutoCalcQ`** `0x2058d0`, 876 bytes: Sets w = 1 on the packet's type-4 vertices, transforms them with RhGeom_MulMatrixVectorArray under the given matrix (the world-screen matrix when 0) between RhGeom_PushMatrix/PopMatrix, divides by w, and writes 16 * x and 16 * y as shorts and the depth into a 24-bit field of each type-4 entry; for packet flags 0x30 without 0x800 it also scales the preceding type-1/type-2 entries by 1/w. Returns 0 when a vertex has z outside 1..16777215 or x/y outside 0..4095, else 1 and the average w through the last argument.

- **`Ex3d_GetSampleZ`** `0x205d10`, 212 bytes: Sets w = 1.0 on the point, transforms it by the world-view matrix, moves it by dz along view z and transforms the result by the view-screen matrix; returns 0xfffff6 when w <= 0, 0 when z <= 0, else func_001a23b0(z / w), apparently the screen depth of the offset point.

The edge vectors start as copies of the constants at data_00293d60 and data_00293d70, which supply their w.
- **`Ex3d_GetPointsAverage`** `0x206030`, 188 bytes: Zeroes out, returns 0 for count 0, else sums count four-float vectors and divides each component by count; returns 1.
- **`Ex3d_GetViewVector`** `0x2060f0`, 252 bytes: Zeroes out and returns 0 for count 0; otherwise averages origin minus point over count points (16-byte stride; a null origin counts as zero), normalises the result with RhGeom_NormalizeVector and returns 1.

- **`Ex3d_GetSurfaceC`** `0x2062f0`, 320 bytes: Plane through three points; out[0..2] expanded cross-product normal, out[3] plane term, out[4] = func_001a6c60 (apparently sqrtf) of the squared normal length.
- **`Ex3d_IntersectP`** `0x206430`, 248 bytes: Intersects the segment p1-p2 with a plane (nx, ny, nz, d; the point satisfies n·p + d = 0), replacing a denominator smaller than 1e-6 in magnitude with +1e-6, and stores p1 + t(p2 - p1) with w = 1.0 in out; no return value.

- **`Ex3d_ViewClip`** `0x206d00`, 40 bytes: Clips a polygon against the six view planes: Ex3d_Clipping(6, gEx3d_aPlane, ...) with its own five arguments, returning the resulting vertex count.
- **`Ex3d_Clipping`** `0x206d30`, 960 bytes: Clips a polygon of 48-byte vertices against 20-byte plane records in turn. Returns count unchanged when it is below 2; otherwise limits it to 341 and, per plane, computes for each vertex and its successor (index (i+1) % count) the distance (x*px + y*py + z*pz + d) / e: both negative drops the vertex; both non-negative copies it to work; otherwise it calls Ex3d_DivideN(cur, next, flags, &cut, |d0| / (|d0| + |d1|)), copies the vertex first when d0 is non-negative and then the cut. The scan stops when 341 outputs are reached; with fewer than 3 input vertices the output count is limited to the input count; work is copied back to vertices and becomes the next count. When bit 0 of flags is clear the two floats at +0x18 of the first vertex are saved before and restored after. Argument types and the unused fifth argument are assumed.
- **`Ex3d_NodeL2V`** `0x2070f0`, 308 bytes: Transforms count 48-byte vertices in place by the given matrix (the world-view matrix when null) with w set to 1.0, summing their z, then clips them against the six view planes with Ex3d_Clipping when the last clip argument is non-negative; stores the sum divided by the resulting count through average when given and returns the count.
